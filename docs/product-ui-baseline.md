# PrivateCloudDrive V0.2 产品化 UI 基线

## 1. 定位

V0.2 的产品目标是“私有部署内测版”，不是继续扩展功能清单。UI 目标是把当前 MVP Core 从“能跑通的工程界面”收口成“可长期使用的私有云盘工具界面”。

本文件是 V0.2 的执行基线，优先级高于零散页面偏好；`docs/ui-design.md` 可作为完整设计参考，但 V0.2 只落地本文定义的核心规则。

## 2. 产品原则

- 工具优先：文件名、缩略图、大小、时间、上传进度、错误原因必须比装饰元素更突出。
- 稳定优先：刷新、上传、删除、恢复、退出登录等高频动作位置稳定，不随状态变化跳动。
- 私有部署优先：明确展示当前 API 地址或服务状态，方便内测人员判断自己连的是哪套私有服务。
- 中文优先：默认中文文案完整、克制、可执行；英文只作为后续本地化补充。
- MVP 不扩张：UI 可以为 V1 能力预留入口，但不能让微信登录、分享、标签、收藏阻塞账号密码登录和文件管理主流程。

## 3. V0.2 信息架构

底部导航保持当前五个入口：

| 入口 | 用途 | V0.2 规则 |
| --- | --- | --- |
| 文件 | 文件夹、文件列表、上传、新建文件夹、下载、删除 | 登录后默认进入；必须能完成 MVP Core 文件主链路 |
| 媒体库 | 图片、视频时间线浏览、处理状态和预览入口 | 必须能同时浏览图片与视频；没有媒体时必须给出明确空状态 |
| 相册 | 图片和视频集合管理 | 必须能查看相册列表、新建相册并进入相册详情 |
| 上传 | 上传队列、失败、完成记录 | 必须能看到上传中、失败、完成三类状态 |
| 设置 | 账号、服务、安全、回收站、日志、退出 | 回收站必须从这里进入，作为 V0.2 明确验收路径 |

非底部导航页面：

- 启动页：检查本地会话和 Token。
- 登录页：账号密码登录为主入口；微信登录仅在平台能力可用时显示。
- 文件详情页：展示文件基础信息和低风险操作；V1 操作必须保持次级。
- 图片预览页：专注查看图片，不展示复杂管理面板。
- 视频播放页：优先播放稳定性和返回路径。
- 回收站页：恢复、永久删除、清空必须二次确认。
- 操作日志页：作为 V1/管理能力入口，可从设置进入。

## 4. 视觉基线

### 4.1 色彩

使用当前 MAUI 色彩方向继续收口：

| Token | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| PageBackground | `#F7F9FC` | `#0F1720` | 页面背景 |
| Surface | `#FFFFFF` | `#161F2A` | 列表、面板、底部导航 |
| SurfaceAlt | `#F1F5F9` | `#1F2937` | 输入框、轻按钮、占位背景 |
| Primary | `#1F7A5C` | `#7EC9B0` | 主按钮、选中态 |
| TextPrimary | `#17202A` | `#F8FAFC` | 主文本 |
| TextSecondary | `#607083` | `#B6C2CF` | 元信息、说明 |
| Border | `#E2E8F0` | `#2D3748` | 分割线、轻边框 |
| Danger | `#B42318` | `#FF8A80` | 删除、永久删除、错误 |
| Success | `#15803D` | `#86D99A` | 上传完成、成功状态 |

落地规则：

- 主色只用于关键动作和选中态，不做大面积背景。
- 删除、清空、解绑、退出登录统一使用 Danger 语义。
- 不使用营销感渐变、装饰背景、巨大 Logo 区块。
- 页面整体不能呈现单一绿色主题；应以中性色为主、绿色为动作色。

### 4.2 字体与密度

| 层级 | 字号 | 用途 |
| --- | --- | --- |
| PageTitle | 22 | 页面主标题 |
| SectionTitle | 17 | 面板或分组标题 |
| Body | 15 | 文件名、正文 |
| Meta | 13 | 时间、大小、路径、服务地址 |
| Caption | 12 | 状态、辅助信息 |
| Button | 15 | 按钮 |

规则：

- 不按屏幕宽度动态放大标题。
- 按钮文字必须完整显示；如果空间不足，优先换行或缩短文案。
- 文件列表以可扫描为核心，避免每条记录过高。
- 文案不解释功能存在本身，只说明当前状态和可执行动作。

### 4.3 圆角、边框、间距

- 页面左右边距：手机 16-18，平板/桌面后续再适配。
- 触控目标：不小于 44 x 44。
- 常规圆角：8。
- 缩略图圆角：6-8。
- 禁止卡片套卡片。
- 列表可以使用轻边框或分割线，但不能把所有页面都做成浮动卡片堆叠。

## 5. 核心页面基线

### 5.1 启动页

必须包含：

- 产品标识。
- 当前状态：正在检查登录状态、检查失败、需要重新登录。
- 失败后的重试入口。

不做：

- 欢迎页轮播。
- 营销说明。
- 多余功能介绍。

### 5.2 登录页

必须包含：

- `PrivateCloudDrive` 产品名。
- 当前 API 地址，作为内测诊断信息。
- 账号/邮箱输入框。
- 密码输入框。
- 主按钮：登录。
- 登录中状态和错误文案。

规则：

- 账号密码登录必须始终可见。
- 微信登录默认隐藏；只有平台能力和后端配置可用时才显示。
- 不增加注册、找回密码、第三方登录扩展作为 V0.2 阻塞项。

### 5.3 文件页

必须包含：

- 页面标题和当前服务地址。
- 当前路径。
- 刷新、新建文件夹、上传入口。
- 文件夹/文件列表。
- 空文件夹状态。
- 加载、失败、重试状态。

列表项必须显示：

- 类型标识。
- 名称。
- 文件类型或文件夹标识。
- 大小。
- 修改时间。
- 详情/更多入口。
- 删除入口。

规则：

- 根目录和子目录必须有清晰返回路径。
- 删除进入回收站，不直接永久删除。
- 上传完成后文件列表应可刷新确认。

### 5.4 媒体库页

必须包含：

- 媒体数量或状态。
- 全部、图片、视频分段筛选。
- 图片和视频缩略图网格。
- 图片预览和视频播放入口。
- 媒体处理状态入口。
- 空状态和加载失败状态。

规则：

- 缩略图加载失败时用稳定占位，不让网格跳动。
- 媒体名称可以弱化，但不能完全不可追踪。
- 图片和视频不再拆成两个底部 Tab。

### 5.5 相册页

必须包含：

- 相册数量或状态。
- 相册封面或类型占位。
- 相册名、媒体数量、更新时间。
- 新建相册入口。
- 相册详情入口。
- 空状态和加载失败状态。

规则：

- 没有相册时必须提供“新建相册”入口。
- 封面加载失败不影响进入相册详情。

### 5.6 上传页

必须包含：

- 上传队列状态汇总。
- 文件名、目标路径、进度、状态。
- 失败原因。
- 清理已完成记录入口。

规则：

- 上传中不能只显示全局转圈，必须展示具体任务。
- 失败任务必须保留错误信息，方便内测记录问题。

### 5.7 设置页

必须包含：

- 当前服务地址。
- 本地会话/安全说明。
- 回收站入口。
- 操作日志入口。
- 退出登录。
- 微信绑定状态可保留，但不能高于回收站和退出登录。

规则：

- 回收站入口必须清晰可见，V0.2 验收路径为“设置 -> 回收站”。
- 退出登录必须二次确认。

### 5.8 回收站页

必须包含：

- 已删除文件列表。
- 恢复。
- 永久删除。
- 清空回收站。
- 空状态、加载状态、失败重试。

规则：

- 永久删除和清空必须二次确认。
- 恢复冲突要给出可理解原因。
- 回收站不是底部 Tab，不能影响主文件浏览效率。

## 6. 组件基线

### 6.1 按钮

- 主按钮：用于登录、上传、恢复等主要正向动作。
- 次按钮：用于返回、重试、详情、进入日志或回收站。
- 危险按钮：用于删除、永久删除、清空、退出登录。
- 同一页面最多一个视觉最重的主按钮。

### 6.2 状态面板

状态面板统一承载：

- 加载中。
- 错误。
- 重试。
- 空状态说明。

错误文案规则：

- 说清楚失败对象，例如“无法加载文件”“无法播放视频”。
- 可附带技术错误短句。
- 不记录密码、access token、refresh token。

### 6.3 列表与缩略图

- 文件列表优先一屏信息密度。
- 媒体库使用三列网格。
- 相册使用两列卡片网格。
- 所有列表必须有空状态。
- 所有可点击项必须有明确反馈或导航结果。

## 7. V0.2 UI 验收标准

V0.2 UI 改造完成后，至少满足：

- Android 模拟器上登录后第一屏不是模板感页面。
- 文件页可以清楚判断当前服务地址、当前目录和主要动作。
- 设置页能明确进入回收站。
- 上传、空文件夹、加载失败、Token 失效后重新登录都有可理解状态。
- 媒体库和相册页面没有大面积空白失控或文本挤压。
- 删除、永久删除、清空、退出登录均有危险态样式和确认。
- 中文文案统一，不混用英文按钮作为默认体验。
- Windows 与 Android 构建通过。

## 8. 当前实施顺序

1. 新增并确认本文档作为 V0.2 UI 基线。
2. 收口 MAUI 全局样式：按钮、面板、列表、输入框、状态信息。
3. 优先改造登录页、文件页、设置页、回收站页。
4. 再收口媒体库、相册、上传、详情页的一致性。
5. 执行 Windows 与 Android 构建。
6. 用 Android 模拟器按 MVP Core 验收路径复查。

## 9. 暂不做

- 不新增后端业务 API。
- 不把微信登录作为 V0.2 阻塞项。
- 不设计营销首页。
- 不做完整品牌视觉资产系统。
- 不做真实手机局域网地址配置化，保留后续独立任务。
- 不做复杂批量选择、移动、重命名、分享管理，除非后续明确进入 V1。
