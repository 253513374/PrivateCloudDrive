# PrivateCloudDrive 公开路线图

日期：2026-05-21
负责人：Hermes 产品总监 / 沈产品
文档定位：公开说明 PrivateCloudDrive 作为开源产品的公司方向、版本边界、迭代优先级和不做事项。

---

## 1. 公司方向

PrivateCloudDrive 继续开发，产品方向收敛为：

> 手机优先的私有备份网盘：让普通用户能把自己的服务器、NAS、迷你主机或云主机变成可信任的私人照片/视频/文件备份中心。

公司当前不追求“大而全网盘”，而是优先证明一个更窄但更有信任价值的问题：

```mermaid
flowchart LR
    A[连接自己的后端] --> B[知道数据存在哪里]
    B --> C[备份照片/视频/文件]
    C --> D[看到进度和失败原因]
    D --> E[可以重试]
    E --> F[可以恢复]
    F --> G[理解隐私与风险边界]
```

---

## 2. 当前阶段：Private Backup MVP

### 目标

让产品具备最小可信闭环：

- App 能配置/识别后端地址。
- 用户知道文件存储位置和服务健康状态。
- 手机文件/照片/视频能批量备份。
- 上传进度、失败、重试、登录过期等状态可理解。
- 用户能根据文档或 App 指引恢复数据。
- 隐私边界、密钥边界和本地/云存储差异说明清晰。

### 常驻团队

当前常驻小队为 11 人：何司令、沈产品、白分析、游体验、莫移动、侯后端、石存储、杜运维、和隐私、秦质检、芮发布。完整团队模型见 `docs/team-operating-model-private-backup.md`。

## 3. 版本路线

| 阶段 | 目标 | 状态 |
|---|---|---|
| Private Backup MVP | 手机备份可信闭环 | 当前主线 |
| V1.0 Public RC | 面向开源用户的可部署、可验证、可恢复版本 | 下一发布目标 |
| V1.1 Operations | 健康检查、备份恢复、升级回滚、管理员运维体验 | 下一阶段 |
| V1.2 Media Library | 更完整的照片/视频时间线、相册、媒体处理状态 | 在主链路稳定后推进 |
| V2 Family/Team | 家庭空间、小团队空间、权限、桌面同步、AI 搜索候选 | 暂不启动 |

---

## 4. Now / Next / Later / Not Now

### Now

- 开源仓库发布与文档完整性。
- Private Backup MVP 收口。
- Android App 真实页面验收。
- Docker 本地栈和备份恢复演练。
- 密钥、隐私和部署边界说明。

### Next

- 公开 Issue/PR 流程。
- CI 基础验证。
- 服务健康页和存储健康页。
- 用户可读的故障诊断向导。
- 更稳定的备份队列、断点/重试策略和恢复演练。

### Later

- 家庭成员空间。
- 多用户容量和权限。
- Web 管理端。
- 更多对象存储后端。
- 媒体库深度增强。

### Not Now

- NAS OS / RAID / 磁盘池。
- SMB/NFS/AFP。
- BT/磁力/下载器平台。
- Office 在线协作。
- 企业审批流。
- AI 相册/AI 搜索。
- 桌面同步客户端。

## 5. 公开贡献优先级

| 优先级 | 方向 | 示例 |
|---|---|---|
| P0 | 数据安全与备份恢复 | 恢复演练、备份校验、删除/恢复边界 |
| P0 | 部署可信度 | Docker、HTTPS、环境变量、健康检查、日志 |
| P0 | 移动备份体验 | 进度、失败重试、弱网、登录过期、恢复入口 |
| P1 | 文档和故障排查 | README、部署教程、FAQ、已知限制 |
| P1 | 自动化测试 | 后端测试、Compose 验证、MAUI 构建验证 |
| P2 | 媒体库体验 | 时间线、相册、封面、处理状态 |

## 6. 进入开发的硬门槛

任何功能进入开发前必须说明：

1. 解决哪个真实用户场景。
2. 是否帮助备份可信闭环。
3. 涉及哪些数据、权限、密钥或删除/恢复流程。
4. 如何验证、如何截图或记录证据。
5. 如何回滚或降级。
6. 文档是否需要同步更新。

回答不清楚的需求不进入当前版本。
