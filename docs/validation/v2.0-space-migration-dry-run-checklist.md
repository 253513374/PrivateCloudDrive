## 5. 业务抽样 SQL

```sql
-- 每个默认空间都有 Owner 成员
SELECT count(*) AS spaces_without_owner_member
FROM "AppSpaces" s
LEFT JOIN "AppSpaceMembers" m ON m."SpaceId" = s."Id" AND m."UserId" = s."OwnerUserId" AND m."Role" = 0
WHERE s."IsDefaultPersonal" = true AND m."Id" IS NULL;

-- 文件节点 SpaceId 与默认个人空间 Owner 一致
SELECT count(*) AS file_nodes_space_owner_mismatch
FROM "AppFileCenterFileNodes" fn
JOIN "AppSpaces" s ON s."Id" = fn."SpaceId"
WHERE s."IsDefaultPersonal" = true AND s."OwnerUserId" <> fn."OwnerId";

-- 分享来源 SpaceId 与目标文件一致
SELECT count(*) AS shares_space_mismatch
FROM "AppFileCenterFileShares" sh
JOIN "AppFileCenterFileNodes" fn ON fn."Id" = sh."FileNodeId"
WHERE sh."SpaceId" IS DISTINCT FROM fn."SpaceId";
```

全部应为 0；否则 FAIL。

## 6. 回滚演练

```bash
psql "$CONNECTION_STRING" -v ON_ERROR_STOP=1 -f scripts/sql/v2.0-space-rollback-postgresql.sql | tee v2-space-rollback-dry-run.log
```

- [ ] 回滚脚本退出码为 0。
- [ ] 回滚后核心表记录数与迁移前 baseline 一致。
- [ ] 旧 V1.x 应用可按 `OwnerId` 路径读取文件列表。
- [ ] 若回滚前存在 `non_default_spaces > 0` 或 `non_owner_members > 0`，本次演练标记为 WARN/FAIL，并补充数据归档方案。

## 7. PASS / WARN / FAIL 判定

| 判定 | 条件 |
|---|---|
| PASS | 所有核心表 before/after 计数一致；核心 `SpaceId` 空值为 0；默认空间和 owner membership 完整；回滚演练可恢复旧结构 |
| WARN | 仅历史 `OperationLogs.SpaceId` 有 null，且能解释为孤儿/历史审计；没有影响文件主链路 |
| FAIL | 任一核心业务表记录数变化、`FileNodes/BlobObjects/Shares/Tags` 存在 null `SpaceId`、同空间唯一冲突、FK 添加失败、回滚后旧应用不可读 |
