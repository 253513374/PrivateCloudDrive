## 1. 总体结论

本次复核覆盖 `docs/release-plan-v1.1.md` §9 G2 发布闸门，以及 TD-01/TD-02/TD-03/TD-05 的后端安全边界。结论：

- 搜索 `SearchScope=All` 仍强制按 `TenantId + OwnerId` 过滤，未发现跨用户读取路径。
- 排序字段未拼接原始字符串，未知值降级到默认排序，未发现 SQL/动态表达式注入路径。
- 批量操作统一做 100 项上限、去重、空 Guid 过滤，并逐项走 owner/tenant 校验。
- 操作日志 DTO 不返回 Password / Token / Secret / Parameters / Exceptions 等高敏字段，批量关键动作有审计动作分类。
- 仍建议修复健康检查路径脱敏一致性、文件列表 DTO 数据最小化问题；测试阶段还暴露 NuGet 高危依赖告警，应由工程侧单独跟踪。

## 4. 是否阻塞发布

- 对 G2 主范围（搜索越权、排序 allowlist、批量逐项校验、操作日志脱敏）：不阻塞 V1.1 发布。
- 建议发布前处理或至少登记的事项：
  1. 中风险：统一健康检查路径输出和日志脱敏，避免完整物理路径进入日志/诊断建议。
  2. 低风险：普通文件列表 DTO 去除 `BlobName` 等内部字段，落实最小披露。
  3. 范围外但需工程侧确认：NuGet 高危漏洞告警是否影响运行时，若影响生产依赖则应阻塞公开发布直至升级或风险接受。

## 5. 下游建议

- 指派 backend-eng 修复 `DeploymentHealthCheckService` 路径脱敏一致性、补批量回滚真实断言、纠正单项 `PermanentDeleteAsync` 审计映射。
- 指派 backend-eng / devops-eng 跑 NuGet 漏洞依赖树并升级或给出风险接受。
- 文件列表 DTO 最小化可以作为 V1.1 后续安全加固，不建议因该低风险项阻塞当前 G2 主闸门。
